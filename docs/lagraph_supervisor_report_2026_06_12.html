1. 一句话概括

LaGraph 目前最适合被讲成一个 面向工业控制系统的多变量异常诊断框架： 它先用重构式时序模型检测异常事件，再在模型预测出的异常事件内部，对变量进行根因相关性排序。 当前论文价值不在于异常检测 F1 全面超过 SOTA，而在于 预测事件内变量级根因排序、图结构约束的多证据排序方法 和 可审计的解释证据。

WADI MRR 0.596

predicted-event 变量级 RCA，Hit@1 0.500，Hit@3/5 0.714。

最能讲的结果
SWaT MRR 0.509

predicted-event 变量级 RCA，Hit@1 0.394，Hit@3 0.576，Hit@5 0.667。

需要克制
不是检测 SOTA

WADI/SWaT raw F1 仍弱，检测应作为诊断入口，而不是论文唯一卖点。

汇报时建议先定边界：当前证据支持“工业异常传播条件下的变量级根因排序”和“机制感知的图结构诊断证据”， 不支持 “严格因果发现”、 “通用异常检测 SOTA” 或 “所有指标全面领先”。

2. 通俗介绍这个项目

工业控制系统里有很多传感器和执行器，例如水处理系统里的液位、流量、阀门、泵状态等。 这些变量不是独立变化的：一个阀门异常可能影响水流，再影响液位，最后让很多变量一起异常。 因此，一个实际问题是：模型不只要告诉我们“哪里异常了”，还要告诉我们“最应该先查哪个变量”。

LaGraph 试图解决的就是这个问题。它把多变量时间序列切成窗口，学习正常运行时的重构模式； 如果某个时间段重构误差变大，就认为这个时间段可能异常。更重要的是，它进一步把异常事件内部每个变量的证据拆开： 哪些变量残差大，哪些变量与邻居变量的正常关系被破坏，哪些变量在事件早期先异常，哪些变量可能只是下游传播响应。 最后模型给出一个变量排序，运维人员可以优先排查前几名变量。

输入多变量工业时间序列窗口，例如 WADI/SWaT/HAI 的传感器与执行器信号。
建模用重构模型学习正常模式，同时学习通道图和时序图。
检测输出每个时间点的异常分数，并切成预测异常事件。
诊断在预测事件内部聚合变量级证据，形成 RCA 排名。
解释输出变量级和子系统级结果，并用消融/faithfulness 检查解释是否可信。

一个通俗类比是：异常检测只是报警器，告诉你“系统有问题”；LaGraph-SB 更像初步诊断助手， 告诉你“先查这几个变量，它们更像事件源头，而不是被波及的响应变量”。

3. 研究问题：从异常检测转向预测事件内 RCA

3.1 原始问题

多变量时间序列异常检测传统上关心“何时异常”。但工业场景里的关键问题常常是“异常从哪里开始”。 直接按重构误差或 z-score 排序会有一个明显缺陷：下游响应变量可能变化幅度更大， 因而被误认为根因。LaGraph 当前主线把问题改写为： 

给定模型预测出的异常事件 e，
输出变量排序 pi(e)，使真实源变量尽可能排在 Top-K 前列。

3.2 为什么 predicted-event RCA 更重要

true-event RCA 是给定真实异常区间后做排序，相当于理想条件下考察解释模块上限； predicted-event RCA 则先由模型自己检测事件，再在预测事件中做排序，更接近实际部署。 后者会同时受到检测漏报、边界偏移、事件分割和变量排序质量的影响，因此更难，但论文价值更强。

协议含义优势风险
true-event RCA 在真实异常窗口内做根因排序。 隔离解释模块能力，适合上限分析。 过于理想，不代表部署链路。
predicted-event RCA 模型先产生预测事件，再在事件内排序变量。 更接近真实使用；能回答“检测后能不能诊断”。 受阈值、事件切分和匹配协议影响，需要透明报告。

4. 方法与系统架构

4.1 当前主线的名称

代码里存在很多 profile，但 2026-06 上旬的汇总文档把 source-bottleneck-specificity-rca 作为当前固定主模型。 它是在早期 full、mechanism-graph 和 mechanism-prior-graph 思路上继续演化出来的诊断型 profile。

时间线需要和导师讲清楚： 5 月底的重点是 mechanism-aware graph 和 graph-edge faithfulness； 6 月上旬的重点已经推进到 WADI/SWaT predicted-event variable-level RCA， 当前更可汇报的是 source-bottleneck-specificity 这条线。

4.2 主干模型

模块作用当前定位
MoE decomposition 把输入窗口拆成趋势与残差，残差更敏感于异常。 保留为重构主干的一部分。
Channel adaptive graph 学习变量之间的依赖图，用于通道消息传递、机制违背和 RCA 证据。 核心模块，但不能直接声称因果图。
Temporal graph / EncoderStack 建模窗口内部时间动态，多尺度时序卷积和注意力提取时序表示。 检测主干的一部分，不宜单独夸大。
VQ bottleneck 作为训练侧正常模式正则，帮助稳定表示。 不应作为主要异常评分贡献。
Direct reconstruction score 用 top-k 通道重构误差形成时间点异常分数。 主要检测信号，稳定可解释。

4.3 RCA 评分思想

当前 RCA 不是只看一个变量误差，而是把事件内证据融合起来。概念上可以理解为： 

RCA_score_i(e)
  = residual_i(e)
  + mechanism_i(e)
  + onset_i(e)
  + source_gate_i(e)
  - propagation_i(e)
  - specificity_i(e)
证据分量直观含义能支持什么不能支持什么
residual 事件内该变量重构误差多大。 变量异常响应强。 不能单独证明它是源头。
mechanism 变量能否被图邻居按正常机制解释。 正常依赖关系可能被破坏。 不能等价于物理因果边。
onset 事件早期是否先出现异常证据。 有助于区分源头与后续传播。 不能排除存在延迟或控制回路效应。
source gate / bottleneck 把大量异常响应压缩成少数更可能源变量。 符合工业排查的 Top-K 需求。 不是严格因果识别。
propagation suppression 降低更像下游响应变量的排序。 缓解残差排序偏向响应变量的问题。 不能完整重建传播路径。
event specificity 惩罚跨事件反复排名靠前的通用响应变量。 提升 WADI 源变量排序。 目前偏导出阶段校准，需要在线版本和消融验证。

5. 当前可以站住的创新点

创新点 1

异常传播条件下的变量级根因排序

工业异常发生后，影响会沿设备连接、控制回路和工艺流程传播。 下游响应变量的异常幅度可能大于真正故障源变量，导致按残差、重构误差或注意力分数排序时， 模型容易把响应变量排在故障源变量前面。本文研究的科学问题是： 在事件边界由模型预测得到、异常传播已经发生的条件下，如何利用多种诊断证据提高故障源变量在排序结果中的位置。

技术抓手：图结构约束的多证据可学习变量排序，联合异常强度、异常起始时间、局部机制变化、传播关系和事件内变量特异性；证据来自 WADI/SWaT 变量级 RCA 主表和相关消融。

创新点 2

多证据排序，而非单一异常分数

方法不直接把残差最大的变量当作根因，而是把异常幅度、起始时序、机制变化、传播关系和事件内特异性拆成不同证据。 可学习参数用于校准这些证据在不同事件中的可靠性，而不是用黑盒分数替代诊断逻辑。

证据：residual-only、z-score、静态相关图等基线，以及 no source gate、no source-propagation、no specificity 等消融。

创新点 3

机制感知图证据

通道图不只是 message passing，而被赋予“用邻居解释目标变量”的机制任务。 早期 mechanism-prior-graph 进一步用弱正常相关先验提升 learned-edge faithfulness。

证据：mechanism-only 高于 random、图边 faithfulness smoke check。

建议论文贡献写法

  1. 本文研究工业异常传播条件下的预测事件内变量级根因排序问题。 其核心挑战是观测到的异常强度同时包含故障源信号和传播响应信号，单一异常分数难以稳定指示根因变量。
  2. 本文提出一种图结构约束的多证据可学习变量排序方法。 方法联合异常强度、异常起始时间、局部机制变化、传播关系和事件内变量特异性，并用可学习参数校准不同诊断证据的可靠性。
  3. 本文在 WADI 和 SWaT 的模型预测事件窗口内评估变量级 RCA。 实验用 Hit@K、MRR 和消融结果验证该排序方法是否能把故障相关变量排到更靠前的位置，同时透明报告检测指标与失败消融。

7.4 子系统级 RCA：好看但不是主贡献

子系统级结果整体较好，例如 SWaT 主线 Subsys-MRR 可到 0.8102 左右，WADI 约 0.79。 但 WADI 的 z-score 子系统 MRR 已达到 0.7679，说明粗粒度定位并不难。 因此子系统级结果适合作为“层级诊断”辅助证据，不应替代变量级 RCA 主表。

9. 下一步计划

9.1 最优先补强

  1. 冻结主实验协议：明确默认 profile、epoch、checkpoint policy、prediction key、RCA label registry、事件匹配规则。
  2. 补齐主表：WADI/SWaT 变量级 predicted-event RCA，外加 raw/adjusted/Affiliation 检测完整表。
  3. 补核心消融：residual-only、z-score、correlation graph、random graph、no source gate、no bottleneck、no propagation、no specificity、no mechanism。
  4. 补稳定性：至少 3 seed，报告 MRR/Hit@K 的均值、标准差、置信区间。
  5. 补案例图：WADI 成功案例、SWaT 成功/近失误案例、失败案例，展示真实根因、top-k 排名、残差排序和 LaGraph 排序差异。

9.2 中期补强

  • 把 AERCA/RCD/CIRCA/REASON/CORAL 中至少 1-2 个代表性 RCA baseline 迁移到当前 predicted-event 协议。
  • 对 mechanism 分量做数据集条件分析：什么时候机制分量有用，什么时候会把 SWaT 排名带偏。
  • 将 event-specificity 从批量后处理改成在线历史事件版本，降低审稿风险。
  • 补充 graph-edge faithfulness 正式实验，不停留在 smoke check。

9.3 长期方向

  • 从同时间依赖图发展到 lagged mechanism / Granger-style 约束，使“机制”更接近可检验因果结构。
  • 引入 edge-level counterfactual 或 interventional masking，证明图边不是装饰性解释。
  • 寻找更多带变量级 RCA 标签的工业控制数据集，避免 WADI/SWaT 过窄。

10. 汇报建议与可讨论问题

10.1 建议汇报主线

  1. 先讲场景：工业异常会沿设备连接、控制回路和工艺流程传播，最大异常分数不一定对应故障源。
  2. 再讲科学问题：在模型预测出的异常事件内，如何避免下游响应变量被排在真正故障源变量前面。
  3. 讲技术方案：重构主干负责发现事件，图结构约束的多证据可学习排序负责在事件内给出变量级根因排名。
  4. 讲证据：WADI/SWaT 变量级 RCA 在 MRR 和 Hit@K 上超过 residual-only、z-score、random、static graph 等本地基线。
  5. 主动讲风险：不是检测 SOTA，不是因果发现，机制分量对 SWaT 不稳定。
  6. 最后请导师判断：论文应该主打预测事件内变量级根因排序，还是继续补机制图/因果图贡献。

10.2 可以直接问导师的问题

  • 投稿目标更适合 EAAI/ESWA/KBS 这类应用 AI 期刊，还是继续补强后冲 IEEE TII/TASE？
  • 外部 baseline 优先复现 AERCA、REASON/CORAL，还是更简单的 occlusion/gradient/Granger baseline？

10.3 一页总结稿

推荐口径： 我们现在不把 LaGraph 讲成一个新的通用异常检测 SOTA，而把它讲成工业异常诊断框架。 当前最强证据是预测事件内变量级根因排序：模型自己先预测异常事件，再在事件内对变量进行根因相关性排序。 这个问题的核心难点是异常传播会放大下游响应变量，导致单一异常分数难以稳定指示故障源。 WADI 和 SWaT 上，图结构约束的多证据可学习排序在 MRR 和 Hit@1 上明显超过随机、z-score 和静态相关图基线。 同时我们也发现机制图并非稳定提升所有数据集，因此论文应该克制地声称面向工业异常传播的变量级根因排序， 而不是严格因果发现。
